## The auto-reply email — what it must be built on

Read against `src/lib/email.ts` as it stands after ticket 033. Phase 2 must reuse all of this rather
than write a seventh way to send mail:

| Existing piece | Where | Why the auto-reply needs it |
|---|---|---|
| `sendEmail(to, subject, html, opts)` | `:992` | The one send path. Carries the preview sink, the no-API-key dev branch, and the swallow-and-log `catch` that keeps a mail failure from failing a request |
| `opts.text` via `htmlToText(html)` | `:117`, `:984` | An HTML-only message with no text part is a spam signal. Generated from the HTML so the copy stays in one place |
| `opts.replyTo: SUPPORT_EMAIL` | `:988` | Without it a customer who hits reply reaches nobody |
| `logoImgTag()` | `:31` | Live logo from site branding, with the cache-busting version |
| `dir` per locale + `listPad` | `:640-641` | RTL bodies, and list indentation that flips with direction |
| `escapeHtml` | `:101` | **Mandatory here.** The auto-reply echoes a customer-supplied name and reference into HTML |
| `EmailLocale` / `toEmailLocale` | `:70-74` | Three locales with a safe fallback |

### Simi and Sima — explicitly required

`EMAIL_CHARACTERS` at `:51` holds four poses as PNG in `public/characters/email/`, deliberately separate
from the site's AVIF/WebP assets because Outlook for Windows renders neither, and deliberately limited to
pair poses and camera-facing figures because Outlook also ignores CSS `transform`, so nothing that points
can be mirrored for RTL.

`reassuring` (open palm, hand on chest, 198×150) is the pose that exists for exactly this situation — it
was cut for `sendOrderDelayedEmail`, whose job is also "we have you, hold on". The auto-reply uses it, one
line under the logo, the same as `:662`. `alt=""`, so a blocked image leaves a clean gap.

`waving` is the alternative if the acknowledgement should read as a greeting rather than reassurance. That
is a one-word change and worth looking at both in the preview before choosing.

### Regression obligation

Ticket 033 left three assertion scripts behind — `email-verify.mjs`, `email-behavior.mjs` and
`email-lang-check.mjs`, the last of which asserts no rendered email contains two languages. Adding a
template means they must be re-run and the new template added to the preview matrix, not merely eyeballed.
`email-preview.ts` renders every template × he/en/ar and purges its output directory first.
